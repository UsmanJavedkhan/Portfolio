/ Common questions and answers

Frequently Asked Questions

I start by pinning down what the thing actually has to do, then agree the scope in writing so we both know what "done" looks like. After that I build in visible slices – database and API first, then the interface on top – and push to a branch you can follow as it goes. You see working software early rather than a status update, which means problems surface while they are still cheap to fix.
On the backend: Laravel and PHP with MySQL – models, controllers, auth, REST APIs. On the frontend: React and Vue.js with Tailwind, and component libraries like Material UI and shadcn/ui where they earn their place. I have also built with Node and Express against MongoDB, and written Python where the job suited it – the SMILE Compiler on my portfolio is a full lexer-to-codegen pipeline in Python. If a project needs something next to that stack, I will say so before we start rather than learn on your budget.
Most of what you can see on my GitHub I built end to end on my own – database, API, interface and deployment. That is the point of working full stack: fewer handoffs, and no waiting on someone else to finish their half. I am equally happy inside an existing team, picking up tickets and working to someone else’s conventions and review process.
Yes, and it is a lot of what I do. The first thing I do with inherited code is read it and get it running locally before changing anything – guessing at someone else’s intent is how small fixes turn into big regressions. I will tell you honestly what shape it is in, what can be patched and what is cheaper to rewrite, instead of quietly billing for a rebuild you did not ask for.
Feedback is part of the build, not an interruption at the end. There are review points at each stage, and because you can see the work running throughout, most changes land while they are still small. Send notes however suits you – a list, a call, comments on a screenshot. If something you ask for will cause a problem later, I will say so and suggest an alternative; it is still your call.
It depends on scope, but as a rough guide: a marketing or landing site is usually 1–2 weeks; a frontend application with real state, like a cart and checkout flow, is 2–4 weeks; a full stack build with a database, API and admin side is 4–8 weeks. I give you a firm estimate once the scope is agreed, and tell you early if anything threatens it rather than on the deadline.
